|              |                                                              |
| ------------ | ------------------------------------------------------------ |
| **Product**  | Halcyon operations portal (repository: Last-Mile-Labs)       |
| **Document** | Requirements to screens, API routes and tests; tricky cases; gaps |
| **Date**     | 31 October 2026                                              |

This document traces each requirement in [DISCOVERY.md](DISCOVERY.md) section 6 (FR-01 to FR-15, with FR-03a, and NFR-01 to NFR-10) to the portal screen that implements it, the API route behind that screen, and the automated tests that cover it. It then lists tricky cases, what the code does with each, and where each is covered, and ends with the gaps ranked by risk. It reflects the working tree on 31 October 2026, uncommitted changes included. `cd api && npm test` ran 189 tests in 49 suites: 189 pass, 0 fail (run on 31 October 2026). The four Redis rate-limit store tests in [rate-limit-store.test.ts](../api/test/rate-limit-store.test.ts) are skipped unless `REDIS_TEST_URL` is set, and are not in that count. The web app (`web/`) has no automated tests.

## 1. How to read this document

- **Screen** is a portal route under `web/src/app/(portal)/portal/`, with the component that does the work. Screens were confirmed by reading the code, not from their names.
- **API** is a route under `/api`, defined in `api/src/routes/`.
- **Tests** are quoted exactly as `npm test` prints them, so `grep -n "<name>" api/test/*.test.ts` finds them. The exception is names built from a list in [bad-input.test.ts](../api/test/bad-input.test.ts): those starting `api-order/`, `carrier-plan/` or `an API order to`. Find those in the `npm test` output, or grep the sample's path. All test files are in [`api/test/`](../api/test/).
- "Web only" means the behaviour lives in the browser and no automated test reaches it.
- Sample files are in [`samples/`](../samples/README.md). [bad-input.test.ts](../api/test/bad-input.test.ts) loads every file in `api-order/`, `carrier-plan/`, `client-answers/`, `delivery/`, `email/`, `email-agent-replies/` and `rebalance/`. No test loads [`samples/test-orders/orders.json`](../samples/test-orders/orders.json) or anything in [`samples/unseen/`](../samples/unseen/README.md).

Roles: **admin**, **contributor** (staff) and **client**. Staff routes are `/api/emails`, `/api/stockouts`, `/api/rebalance`, `/api/carrier-plan`; client routes are `/api/order-requests`; admin only are `/api/staff`, `/api/audit`, `/api/simulation` and `PUT /api/settings/delivery`.

## 3. Tricky cases

"Confirmed" means read in the code. Cases touched by the changes up to 31 October 2026 were read again on that date; the others rest on the reading of 30 October, as their code has not changed since. "Not verified" means the outcome depends on something not read or not run. Web behaviour is confirmed by reading only, as no test runs it. Sample files are linked where one exists.

| # | Case | What the system does | Covered by |
| --- | --- | --- | --- |
| T1 | Order received at exactly 08:00:00 New York time | Next day. The rule compares the local "HH:MM" with the cutoff using `>=`, so 08:00 counts as after; 07:59:59 is "07:59" and is same day. Highest risk first. "Risk" weighs how likely the case is at today's volume (about 270 orders a day) against what goes wrong.

| --- | --- | --- | --- |
| 1 | Auto-routing and the Resolve status are web only, with no tests: `autoRouteOf` and the status in `buildRequest` still have none.
